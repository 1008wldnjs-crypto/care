# 재가요양 / 방문케어 앱 — 제품 명세 (1차)

> 스택: React Native  
> 상태: 확정된 요구만 기록. 미확정은 [미확정]으로 표시.  
> 화면 흐름: `docs/app-flow.md`

## 0. 한 줄 설명

노인 본인이나 보호자가 **청소**, **돌봄(케어)**, **식사** 등  
대신해 줘야 하는 일을 **신청**할 수 있는 앱이다.

**목표:** 가격·정보·신뢰 허들을 낮춰, 필요한 사람이 망설임 없이 서비스를 이용하게 한다.

### 간단 동작 흐름 (소비자)

```
앱 실행
  → 카테고리 선택
  → 세부 카테고리 선택
  → 일정 선택
  → 예상 가격 안내
  → 신청 요약
  → 사회복지사 매칭
  → (매칭 후) 채팅
  → 서비스
  → 도움 완료 후 결제 → 리뷰
```

## 1. 앱 구성 (확정)

| 앱 | 주 사용자 | 역할 |
|------|-----------|------|
| **소비자 앱** | 노인, 보호자 | 서비스 요청, 매칭 선택, 결제, 채팅, 리뷰 |
| **사회복지사 앱** | 사회복지사 등 전문가 | 의뢰 열람·지원, 일정 수행, 채팅, 정산 확인 |

> 앱은 **위 2개만** 만든다. 관리자 전용 앱은 없다.

## 2. 해결하려는 허들

| 허들 | 앱에서의 대응 |
|------|----------------|
| 가격 불투명 | 카테고리 → 세부 → 일정 후 **대략 가격** 안내 |
| 정보 부족 | 신청 절차를 화면 플로우로 안내 |
| 신뢰 약함 | 매칭 전 프로필·후기 / **매칭 후** 채팅·리뷰 |

**1차에서 제외**

- 지역 기반 “우리 동네 후기”
- 알바(시니어 소일거리 — 후순위)
- 정기구독 결제 (상주 포함)

## 3. 카테고리

| 카테고리 | 1차 | 비고 |
|----------|-----|------|
| 운동 | O | 건별 매칭 |
| 청소 | O | 건별 매칭 |
| 케어 | O | 세부: **목욕, 세탁, 외출, 병원동행** 등 |
| 상주 | O | 건별과 분리 → 상담 신청 → 1:1 전화상담 |
| 음식 | O | 식사 배달 + (선택) 준비·정리 추가금 |
| 공부 | O | 치매 예방형 인지·학습 |
| 알바 | X | 후순위 |

### 3.1 가격

- 카테고리·세부별 **시간당 고정 단가표**
- `대략 가격 = 단가 × 시간`
- 단가표는 앱에 심는다 (코드/설정 고정)
- **임시 단가:** `care-consumer/src/data/catalog.ts` (숫자만 교체 가능)

### 3.2 상주

- **1차: 상담 신청만** (구독·앱 내 결제 없음)
- 선택사항 체크 → 「상담 신청 완료」 → **1:1 전화상담**
- [미확정] 선택사항 체크 항목 목록

### 3.3 음식

- 기본: 어른용 식사 배달
- 선택: 식사 준비·정리 (추가금)

### 3.4 케어 세부 (확정)

- 목욕
- 세탁
- 외출
- 병원동행
- (필요 시 기타 세부 추가 — [미확정])

## 4. 핵심 유저 플로우

### 4.1 소비자 — 건별

```
앱 실행 → 회원가입/로그인 → 기본설정(주소)
  → 카테고리 → 세부 → 일정(정기/일회)
  → 예상 가격 → 신청 요약 → 신청
  → 매칭 대기 / 지원자 선택
  → (매칭 후) 채팅
  → 서비스
  → 완료 후 결제 → 리뷰
```

### 4.2 매칭 규칙 (확정 — 기존안)

| 상황 | 동작 |
|------|------|
| 지원자 1명 | 자동 매칭 |
| 지원자 여러 명 | **별점 순 목록** → 소비자 **직접 선택** |
| 지원자 없음 | **재요청 1회** → 없으면 **고객센터** |
| 방문 24시간 전 미매칭 | **조건 조정 제안** (일정·시간) |

**매칭 전:** 담당자 프로필, 후기  
**매칭 후:** 채팅 (매칭 전 채팅 불가), 서비스 후 리뷰

### 4.3 취소·재매칭·환불

| 시점 | 규칙 |
|------|------|
| 매칭 전 | 무료 취소 |
| 매칭 후 ~ 서비스 시작 24시간보다 이른 시점 | 무료 취소 |
| 서비스 시작 **24시간 전** 이후 | 취소 수수료 (아래) |
| 제공자 지원 취소 (결제 전) | 재매칭 큐 + 고객에 “담당자 변경 중” |
| 노쇼 | 서비스 금액 **100%** |

**고객 취소 수수료**

| 시점 | 수수료 |
|------|--------|
| 24시간 전 이후 ~ 12시간 전 | **n%** [미확정] |
| 12시간 전 이후 ~ 시작 전 | **n%** [미확정] |
| 노쇼 | **100%** |

### 4.4 사회복지사 — 지원

```
의뢰 목록 → 상세 → 지원하기 → 매칭 확정
  → (매칭 후) 채팅 → 서비스 → 정산 확인
```

## 6. 결제

### 6.1 기본 흐름 (확정 — 다이어그램)

```
도움 완료
  → 사용자에게 결제 요청 (기한 내)
  → 결제 (카카오페이 / 신용카드 / 계좌이체)
  → 사회복지사 정산 (**플랫폼 수수료 15%** 차감)
  → 리뷰
```

- **건별 결제**
- ~~사전 20% / 방문 시작 시 청구~~ → **사용하지 않음** (도움 완료 후 청구로 변경)
- **플랫폼 수수료 15%** (확정) — 결제 총액 기준, 정산 시 차감. PG(카드) 수수료는 이 안에서 흡수하는 전제

### 6.2 수수료 구분

| 이름 | 누가 부담 | 언제 | 요율 |
|------|-----------|------|------|
| **플랫폼 수수료** | 정산 시 차감 (복지사 지급액 = 총액 − 15% 등) | 결제·정산 시 | **15%** (확정) |
| **취소 수수료** | 소비자 | 서비스 시작 24h/12h 전·노쇼 | 24h·12h **n%** [미확정], 노쇼 **100%** |

### 6.3 결제수단 (확정)

| 수단 | 1차 | 비고 |
|------|-----|------|
| 간편결제 (카카오페이) | O | 등록 화면 기본 |
| 신용카드 | O | PG 위젯, 카드정보 앱 미저장 |
| 계좌이체 / 무통장 | O | 잔액 부족 시 재시도 → 수동결제 링크 |
| 네이버페이 | Later | — |

**등록 UX**

- 기본: 「카카오페이로 확정하기」
- 「다른 방법으로 등록」: 신용카드 / 계좌이체

**등록 우선순위**

1. 보호자가 미리 등록 (본인 계정 연결)  
2. 본인 간편결제  
3. 고객센터 결제요청 링크 (문자/카톡)
