# 다정 고객용 앱 — 예약 플로우 명세 (UI 명세에 추가)

> 구현 기준: `PRODUCT_SPEC.md`의 공통 UI 규칙(폰트·용어·컬러·아이콘) + 본 문서.  
> 시안과 다르게 임의로 바꾸지 않는다. 시안의 주소·전화번호·금액은 임시 예시이며 하드코딩하지 않는다.

## 0. 먼저 읽을 것

- 앞서 전달한 UI 명세의 공통 규칙(폰트 크기, 용어, 컬러 토큰, 아이콘, 줄바꿈)을 그대로 따른다.
- 예약 플로우 순서 (확정): **1 주소 → 2 일정 → 3 연락처 → 4 케어 항목 → 5 예상 금액 정리·확인·동의 → 6 매칭 → 7 결제수단 등록**
- 실제 **청구·결제는 서비스 종료 후** (`PRODUCT_SPEC.md` §9). 예약 중에는 금액 확인·동의와 결제수단 등록만 한다.
- 이 문서에서 상세하게 정의한 것은 **1~4번**이다. 5~7번은 같은 레이아웃을 쓰되 화면 디자인은 TODO다.
- 시안 기준 화면: 예약 1 주소 / 예약 2 일정 / 예약 3 연락처 / 예약 4 케어 항목.

## 1. 진입

- 홈의 카테고리 카드(운동, 케어, 청소, 음식, 인지 활동)를 누르면 해당 카테고리가 선택된 채로 1번 화면에서 시작한다.
- 홈의 「당일 긴급 요청」 배너를 누르면 일정의 「당일 긴급」이 켜진 상태로 시작한다 (카테고리는 이후 선택 필요, 시작 방식은 TODO).
- 상주는 이 플로우를 쓰지 않는다 (1:1 전화상담 연결).
- 이전 단계로 돌아가도 입력한 값은 유지한다. 앱을 닫아도 입력 중인 예약(draft)은 기기에 저장하고 다시 열면 이어서 진행한다.

## 2. 공통 레이아웃: BookingStepLayout

모든 예약 단계가 공유하는 컴포넌트 하나로 구현한다.

- 상단 바: 왼쪽 뒤로가기 화살표(터치 영역 44px), 오른쪽 「도움이 필요해요」 말풍선(15px, 배경 `#F2EEE8`, 높이 40) + 어두운 원형 「?」 아이콘(28px, 배경 textPrimary, 흰색 「?」). 「?」를 누르면 고객센터 연결 (연결 방식 TODO).
- 진행바: 높이 4, 트랙 border 색, 채움 buttonPrimary. 총 5단계 기준 20% / 40% / 60% / 80% / 100%. 숫자 텍스트는 넣지 않는다.
- 제목: 30px bold, line-height 1.3, 2줄 (`\n`으로 직접 줄바꿈).
- 본문: 스크롤 가능. 키보드가 올라와도 하단 바가 가려지지 않게 처리한다.
- 하단 고정 바: 높이 112 (안전 영역 포함), 흰 배경, 위쪽 구분선 1px border, 좌우 패딩 20.
  - 왼쪽: 안내 문구 15px textSecondary, 최대 2줄
  - 오른쪽: 「다음으로」 버튼 너비 190, 높이 60, radius 30, buttonPrimary 배경, buttonPrimaryText bold 20px
  - 비활성 상태: 배경 `#E5E1D8`, 글자 `#8A8178`, 왼쪽 안내 문구에 무엇이 필요한지 적는다.
- 항목 행(SectionRow): 위에 라벨 20px bold, 아래에 값 19px, 오른쪽 chevron, 아래 구분선 1px border, 위아래 패딩 18. 누르면 입력/선택 화면(바텀시트 또는 새 화면)이 열린다.

## 3. 예약 데이터 (BookingDraft)

- `category`: `'exercise' | 'care' | 'clean' | 'meal' | 'cognitive'`
- `address`: `{ road: string, detail: string }`
- `schedule`: `{ urgent: boolean, date: string, time: string }`
- `contact`: `{ name: string, phone: string }`
- `recipient`: `{ type: 'self' | 'family', name?: string, phone?: string }`
- `careItems`: `string[]`
- `price`: 설정 파일의 단가 규칙으로 계산 (섹션 8 참고)

## 4. 화면 1: 주소

- 제목: `어디로\n방문하면 될까요?`
- 주소 행: 선택한 주소를 최대 2줄로 보여준다. 누르면 주소 검색 후 상세주소(동·호) 입력. 주소 검색 방식은 TODO. 홈의 「주소 입력」으로 저장한 주소가 있으면 미리 채운다.
- 신뢰 배너 (행 아래 28px 간격): greenSoft 배경, radius 20, padding 20. 위 `신원과 자격을 확인한\n사회복지사만 방문해요`(19px bold, green), 아래 「인증 배지가 있는 분만 연결돼요」(15px), 오른쪽에 shield-check 아이콘 52px (green).
- 하단 안내: 주소 없음 「방문 주소를 선택해주세요」(버튼 비활성) / 주소 있음 `방문 주소가 맞는지\n확인해주세요`
- 다음 조건: 주소와 상세주소가 모두 입력되어야 한다.

## 5. 화면 2: 일정

- 제목: `언제\n방문하면 될까요?`
- 「당일 긴급 요청」 카드 (토글): 흰 배경, 테두리 1.5 border, radius 20, padding 16. 왼쪽 zap 아이콘 28px (urgent 색), 가운데 「당일 긴급 요청」(20px bold) + 「지금 바로 필요해요 (긴급 수수료 30% 추가)」(15px textSecondary). 켜지면 테두리 2px urgent + urgentBg 배경.
- 긴급이 켜지면: 날짜는 오늘, 시간은 「지금」으로 고정하고 날짜/시간 행은 숨기거나 비활성 처리한다.
- 긴급이 꺼져 있으면: 「날짜」 행(오늘 이후만 선택 가능, 예: 「10월 20일 (화)」), 「시간」 행(예: 「오전 10:00」)을 보여준다. 각 행을 누르면 선택기가 열린다.
- 하단 안내: 선택 전 「방문 일정을 선택해주세요」(버튼 비활성) / 선택 후 `방문 일정이 맞는지\n확인해주세요`
- 다음 조건: 긴급이 켜져 있거나, 날짜와 시간이 모두 선택되어야 한다.
- 가능한 시간대 범위와 예약 가능 기한은 TODO (설정값으로 분리).

## 6. 화면 3: 연락처

- 제목: `연락 가능한\n번호를 알려주세요`
- 「연락처」 행: 「이름, 전화번호」를 로그인한 계정 정보로 미리 채운다. 아래에 15px textSecondary로 「예약 소식을 이 번호로 알려드려요」. 누르면 수정할 수 있다. 알림 채널(앱 푸시, 알림톡 등)은 TODO.
- 「돌봄을 받으실 분」 선택: 칩 2개 (본인 / 가족을 위해), 한 개만 선택, 기본값은 「본인」. 칩 높이 60, radius 30, 글자 19px. 선택된 칩은 테두리 2px buttonPrimary + orangeSoft 배경 + bold, 선택 안 된 칩은 흰 배경 + 테두리 1.5 border.
- 안내 문구 15px textSecondary: 「가족이 대신 신청하시면 방문받는 분의 연락처도 함께 남겨주세요.」
- 「가족을 위해」를 선택하면 방문받는 분의 이름과 연락처 입력 항목이 나타난다 (필수). 화면 디자인은 TODO이며, 같은 SectionRow 스타일로 만든다.
- 하단 안내: `연락처를\n확인해주세요`
- 다음 조건: 연락처 형식이 올바르고, 가족을 위해 선택 시 방문받는 분 정보가 입력되어야 한다.

## 7. 화면 4: 케어 항목

- 제목: `필요한 도움을\n골라주세요`, 아래 「여러 개 고를 수 있어요」 17px textSecondary
- 선택 목록: 행 높이 64, radius 20, 흰 배경, 테두리 1.5 border, 글자 20px, 행 사이 간격 10, 왼쪽 체크박스 28px (radius 8).
  - 선택됨: 테두리 2px buttonPrimary, orangeSoft 배경, 글자 bold, 체크박스는 buttonPrimary로 채우고 진한 체크 표시(buttonPrimaryText 색)
  - 선택 안 됨: 체크박스는 빈 상자(테두리 2px border)
- 항목은 선택한 카테고리에 따라 달라진다.
  - **케어 (확정):** 부축·이동 도움 / 병원 동행 / 약 챙기기 / 안부·말벗
  - 다른 카테고리의 항목은 설정 파일로 분리한다 (TODO: 카테고리별 항목 확정).
- 하단 고정 바: 왼쪽에 「예상 금액」(15px) 아래 금액(24px bold, textPrimary). 선택할 때마다 바로 갱신한다. 하나도 선택하지 않았으면 「한 가지 이상 골라주세요」로 바꾸고 버튼은 비활성.
- 다음 조건: 항목을 1개 이상 선택해야 한다.

## 9. 이후 단계 (같은 레이아웃, 디자인 TODO)

- **5 예상 금액 정리·확인·동의:** 카테고리, 주소, 일정, 연락처, 선택 항목, 금액 내역을 요약한다. 「매칭 전에는 요금이 청구되지 않아요」「결제는 서비스가 끝난 뒤에 해요」 안내를 넣는다. 예상 금액을 정리한 뒤 **확인 버튼**과 **동의**(필수)를 받고 나서 다음으로 진행한다. 동의 문구·체크 UI는 TODO. 진행바 100%.
- **6 매칭:** 사회복지사가 의뢰에 지원하고, 고객이 지원자 목록에서 한 명을 고른다. 지원자 카드에는 이름, 경력, 후기를 보여준다 (개인별 가격은 표시하지 않는다). 지원자가 없을 때의 대기·취소·재요청 규칙은 `PRODUCT_SPEC.md` §8을 따른다.
